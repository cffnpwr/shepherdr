# UI

## トレイメニュー

メニューバーのトレイアイコンから以下を提供する。

- サービスごとの項目
  - 状態表示（実行中/停止/再起動待ち/失敗）
  - 起動/停止/再起動
- 設定を再読み込み（[サービス管理](./service-management.md)の差分適用）
- ログを開く（ログウィンドウの表示）
- Shepherdrを終了

## ログウィンドウ

ウィンドウはUnified Toolbarとログ領域の2段で構成する。

- ツールバー（高さ52pt）: leading側にウィンドウタイトル、trailing側にサービス選択のポップアップボタン
- ログ領域: 残りの全面を占め、選択中のサービスのログファイルをtail表示する（追記に追従する）
- 検索・フィルター・ローテーション済み世代の閲覧は持たない

### ANSIエスケープシーケンス

子プロセスの出力はパイプで捕捉するためPTYではないが、色付けを強制する指定があるとエスケープシーケンスがログファイルに残る。
ログファイルには手を入れず、表示側で解釈する。

- SGR（文字装飾）のみ解釈し、前景色・背景色・太字・下線・反転・リセットを描画に反映する。
  カーソル制御・行消去を含む他のシーケンスは除去して表示しない。
  ログウィンドウは端末エミュレーターではなく、追記されるテキストを流すものと位置づける
- ANSI 16色はmacOSのsystem colorへマップし、テーマに追従させる。
  black/whiteは既定の文字色/背景色に対応させ、テーマに応じて反転する。
  blackの指定は背景との対比を意図したものとみなし、テーマによらず対比が保たれる側に寄せる
- bright系8色は対応する通常色と同一に扱う。
  macOSのsystem colorに明暗の対がないため
- 256色・24bit色は指定された値をそのまま使う。
  ここだけはテーマに追従しない

## フロントエンド構成

ログウィンドウは、ツールバーをネイティブのAppKitで、ログ領域をTauriのWebViewで描く。

ツールバーをネイティブにするのは、macOS 27のLiquid Glassをはじめとするツールバーの外観をOSに描かせるためである。
WebView側で模倣すると、OSの更新のたびに追随が必要になる。
代償として、ツールバーの見た目をHTML側で制御する自由を失う。
ログウィンドウのツールバーはサービス選択だけを載せる想定なので、この取引は成立する。

WebView側が持つのはログ領域だけになる。

- ランタイム・パッケージ管理: bun
- 言語・ビルド: TypeScript＋Vite
- UI: React（Tailwind CSS）

## デザイン方針

ビジュアルデザインはmacOS 27 UI Kit（Apple Design Resources）に準拠させる。
light/darkはOSのテーマ設定に追従させ、アプリ独自の切り替えは持たない。

ログ本文は等幅フォントで表示し、和文はフォールバックで補う。
システムフォントに頼らず、フォントを配布物に同梱する。

ネイティブのツールバーはOSがシステムフォントで描くため、これらの指定はログ領域にのみ及ぶ。
